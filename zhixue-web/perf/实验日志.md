# 实验日志

每个实验一条记录：假设 → 最小改动 → 棘轮/护栏 → 测量 → 是否保留。

## E1 Element Plus 按需引入

- 假设：全量 `app.use(ElementPlus)` + 全量 CSS 是首屏最大头；改为 `unplugin-auto-import` + `unplugin-vue-components` + `ElementPlusResolver` 后，未使用组件与样式会从产物消失。
- 改动：
  - `vite.config.ts` 接入 AutoImport/Components。
  - `main.ts` 移除 `ElementPlus` 全量注册与 `element-plus/dist/index.css`，保留 dark css vars。
  - 移除 `ElMessage` 显式导入，交给 AutoImport。
  - 删除 `manualChunks` 中 `echarts`/`g6` 空 chunk 与 `element-plus` 强制分包。
- 结果：
  - `element-plus` 独立 chunk 消失。
  - JS 总 gzip 374.65 → 201.44 kB（-46.2%）。
  - CSS 总 gzip 51.82 → 27.25 kB（-47.4%）。
  - 最大 JS chunk gzip 333.93 → 120.37 kB（-64.0%）。
  - 最大 CSS chunk gzip 50.36 → 8.90 kB（-82.3%）。
- 结论：保留。

## E2 Lucide + Element Plus 图标

- 假设：用按需图标替换文字符号并统一菜单视觉，不会显著增加体积；图标组件应被 tree-shaking。
- 改动：
  - 侧栏五项加 Lucide 图标（Stethoscope/BookOpen/Radar/CalendarCheck/Network）。
  - 移动端 `☰` → `Menu`；主题 `▾` → `ChevronDown`。
  - 上传区加 Element Plus `Upload` 图标。
- 结果：最终构建仍在 E1 后的体积棘轮内；图标未单独隔离测量，不能声称“零成本”。
- 视觉冒烟（2026-10-28，生产构建 `npm run preview`，4173）：登录页正常；桌面侧栏 5/5 菜单项均含 SVG；上传区 `.upload-icon` 根节点为 `<svg>`；390×844 抽屉 5/5 均含 SVG；控制台无图标/组件错误。
- 例外：`ThemeSwitcher.vue` 未被任何页面挂载，`ChevronDown` 改动当前无可见效果，属预留；不计入已验收的可见变化。
- 结论：保留；视觉冒烟已通过。

## E3 体积棘轮

- 假设：把当前 gzip 体积写成上限，后续任何让体积变大的 PR 都会在 `npm run build` 失败。
- 改动：
  - `perf/bench/bundle-budget.mjs` 解析 `dist/assets`，检查 JS/CSS 总量与最大 chunk。
  - `perf/bench/ceilings.json` 记录当前上限。
  - `npm run build` 末尾自动执行。
- 结果：`✓ 体积棘轮通过`；当前上限见 `ceilings.json`。
- 结论：保留；后续只许通过 `--update` 下调，不允许无理由上调。
