# 前端性能报告：Element Plus 按需 + 图标体系 + 体积棘轮

日期：2026-10-27

## 结论

首屏最大瓶颈是 Element Plus 全量引入。改为按需引入后，JS 总 gzip 下降 **46.2%**，CSS 总 gzip 下降 **47.4%**，最大 JS chunk 下降 **64.0%**。本轮同时建立确定性体积棘轮，后续构建超过上限会失败。

## 前后对比（同一构建命令，gzip）

| 指标 | 改造前 | 改造后 | 变化 |
|---|---:|---:|---:|
| JS 总 gzip | 374.65 kB | 201.44 kB | **-46.2%** |
| CSS 总 gzip | 51.82 kB | 27.25 kB | **-47.4%** |
| 最大 JS chunk | 333.93 kB | 120.37 kB | **-64.0%** |
| 最大 CSS chunk | 50.36 kB | 8.90 kB | **-82.3%** |

> 注：这是构建产物的确定性体积，不是用户 p75。真实体感结论需用 `perf/bench/bench.py` 或 JMeter 在固定网络/设备下配对测量。

## 改动清单

1. `vite.config.ts`：接入 `unplugin-auto-import` / `unplugin-vue-components` + `ElementPlusResolver`。
2. `src/main.ts`：移除 Element Plus 全量注册与全量 CSS，保留 dark css vars。
3. `src/types/auto-imports.d.ts`、`src/types/components.d.ts`：按需导入生成的类型声明。
4. `src/App.vue`：Lucide 菜单图标 + 移动端 Menu。
5. `src/components/ThemeSwitcher.vue`：ChevronDown。
6. `src/views/DiagnosisWorkbench.vue`：Element Plus Upload 图标。
7. `perf/bench/bundle-budget.mjs` + `ceilings.json`：体积棘轮。
8. `perf/bench/bench.py`、`ratchet.py`：huashu-flash 原始测速脚本（MIT，作者花叔），待安装 Playwright 后使用。

## 验证

- `npm run build`：`vue-tsc --noEmit` 通过，Vite 构建通过，体积棘轮通过。
- 当前棘轮上限：JS 总 206,277 B gzip；CSS 总 27,905 B gzip；最大 JS 123,259 B gzip；最大 CSS 9,116 B gzip。
- 待补：浏览器冒烟（登录页、诊断台、移动端抽屉、主题切换）与 CI 四 job。

## 风险与回滚

- 按需样式可能漏加载；构建已通过，仍需浏览器冒烟兜底。
- 图标是用户可见变化；如不满意，可单独回退图标提交/改动。
- 回滚：`git revert <本次 commit>`；棘轮随代码回滚。
