# 13-代码与注释规范

> 与 `12-FAQ.md` 编号无关，本文为代码与注释规范。

> 适用范围：`zhixue-server`（Java）、`zhixue-web`（Vue/TS）、`zhixue-ai`（Python）与 `tools/` 脚本。
> 总纲：**注释只写代码看不出来的东西——为什么这么做、边界在哪、坑在哪。** 代码本身能读懂的，不写注释；写了就会过期的，宁可指向事实源。
> 判定标准：每条规则都能被人（或一条 grep）在 10 秒内判对错。

## 规则清单（15 条）

### 1. 注释写"为什么"，不写"是什么"

```java
// 正例：解释了不这么做的后果
// 窗口双倍过期，避免边界残留；计数器本身按分钟自然失效
redisTemplate.expire(key, Duration.ofSeconds(WINDOW_SECONDS * 2));
```

```java
// 反例：复述代码，删掉注释信息量为零
// 设置过期时间为窗口的两倍
redisTemplate.expire(key, Duration.ofSeconds(WINDOW_SECONDS * 2));
```

### 2. 注释引用事实源，不复制事实源的内容

契约字段、错误码、阈值数字只在 `docs/openapi.yaml` / `docs/05` / `application.yml` 维护一份；注释只引用条款号。

```java
// 正例
/** 讲解限流（契约 V2 §8：按用户 10 次/分钟，超出 42900 并带 Retry-After） */
```

```java
// 反例：把契约数字复述一遍，契约一改注释就过期
/** 限流：每分钟最多 10 次，第 11 次返回 42900，Retry-After 为剩余秒数，
 *  另外 40000 是参数错误、40100 是未登录、40300 是…… */
```

### 3. 改代码必须同步改同处注释；注释与代码矛盾时以代码为准并立即修注释

判定：任何一行注释描述的行为，与其下方 20 行内代码不一致，即违规。

```java
// 反例（真实案例）：实现是 sha256，注释写 sha1
// 契约 §6：sha1(kpId + errorType + correctedText)，TTL 7 天
String cacheKey = explainCacheService.key(...); // 内部是 SHA-256
```

```java
// 正例
// 契约 §6：sha256(kpId + errorType + correctedText)，TTL 7 天
String cacheKey = explainCacheService.key(...);
```

### 4. 复杂算法/降级链/事务/幂等/越权过滤，类级注释必须写清口径与出处

必须覆盖：算法公式与参数来源、降级链层级、事务边界及为何这样包、幂等的竞态处理、越权过滤的 SQL 条件。

```java
// 正例：口径、出处、旧方案为何被换，一段说清
/**
 * 掌握度：Beta 后验 + 双侧时间衰减 + 90% 可信区间（docs/05 §2）。
 * 旧公式 1 - Σ错误严重度/N 只衰减错误、分母不变，长期不练会逼近 1.0……
 */
```

```java
// 反例：核心服务只有一句空话
/** 知识点服务：完整分层切片示例的 service 层。 */
```

### 5. 新增代码不得引入日期印章式变更日志注释；历史交给 git

判定：**本次改动新增/修改的注释行**含 `YYYY-MM-DD` 形式的变更记录即违规；存量已在「存量豁免与整改计划」A 节登记，不重复计入。文档文件名中的日期（如 `docs/design/mapping-optimization-2026-11-03.md`）是事实源引用，不算印章。

```java
// 反例
/** 2026-10-31 C1：按真实作答写入 is_correct（不再固定 1）。 */
```

```java
// 正例：只描述当前行为
/** 打卡按真实作答写入 is_correct；"仅记录进度"不写 practice_record。 */
```

### 6. 新增注释禁止无信息署名与 AI 痕迹

仅对新增/修改的注释生效；存量见「存量豁免与整改计划」。禁止：`@author`、`Generated by XXX AI`、创建日期、"下面我们…"、感叹语气、emoji（CLI 输出提示符除外）。机器生成文件（如 unplugin 的 `*.d.ts`）不计。

```java
// 反例
/** ✨ 智能讲解服务 🚀 —— 由 AI 助手生成，2026-10-20，作者：小明 */
```

```java
// 正例
/** RAG 流式讲解网关（契约 V2：POST /api/diagnosis/explain，SSE）。 */
```

### 9. 数字要么配置化，要么提常量并注释来源；同一常量跨语言重复必须互相引用

### 11. 异常与日志：禁止空 catch；日志不出现 PII（姓名/学号/手机号）；用户可见文案不泄露堆栈

```java
// 正例：降级有日志、有原因
} catch (Exception e) {
```


### 14. 文件行数：新增代码不得让文件超过警戒线后继续增长（Vue 800 / Java 600 / 脚本 500；测试与离线评测脚本除外）

判定：新文件超过警戒线即违规；存量超线文件已在「存量豁免与整改计划」D 节登记，**只降不升**——任何改动不得让已登记文件行数增加。拆分优先顺序：可复用逻辑抽 composable/service → 视图拆组件 → 数据与断言分文件。

```text

```

### 15. 对外 API 注释：承担业务语义的 public 方法必须有 Javadoc/docstring，写清前置条件、返回语义、错误码

单行透传（controller 直接转发 service）可只靠类级注释 + 路由注解；`@param` 要么写有意义的内容，要么不写。

```java
 * 提交作答（推荐题/自主练习）。
 * 幂等：同一 userId + clientToken 返回首次结果，duplicate=true；不返回 40900。
 */
public PracticeResultView submit(PracticeCreateRequest request) { ... }
```

```java
// 反例：空话 @param
/**
 * 提交
 * @param request 请求
 * @return 结果
 */
```

## 禁止事项清单（一票否决）

1. 提交密钥、口令明文、内网地址到代码或文档示例（示例一律用 `<口令>` 占位）。
2. 注释掉的死代码块留在仓库（要删就删，历史在 git）。
3. 空 catch 块；`catch` 后既不处理也不说明。
4. 注释与代码矛盾仍合入（发现即阻断，改注释或改代码二选一）。
5. 裸 `LocalDateTime.now()` 进主源（新增；存量 6 处见 B 节）。
6. `: any`、无理由 `@ts-ignore` 进 `src/`。
7. `console.log` / `System.out.println` / `debugger` 进主源。
8. 无负责人/issue 号的 `TODO`（新增；存量 1 处见 C 节）。
9. 日期印章、作者署名、AI 生成水印进注释（新增；存量 11 条见 A 节）。
10. 把前端隐藏当权限；日志打印学生姓名/学号等 PII。
