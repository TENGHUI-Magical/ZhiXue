## 1. 知识点映射

### 1.1 输入与输出

输入：题干文本（OCR 校正后）、`courseId`、可选 `chapterId`。
输出：`decision`（AUTO / CONFIRM / FAILED）、`top1`、候选列表（含分数与命中通道）。

### 1.2 预处理

1. 全角转半角，统一小写，保留 SQL 关键字与符号（`SELECT`、`主键`、`FK`）。
2. 去掉题号、"选择题"等无信息前缀。
3. 按课程过滤候选集；若传 `chapterId`，只保留该章知识点。

### 1.3 打分通道（当前实现口径）

> **口径声明（引用数字前必读）**：本节所有指标都来自离线脚本
> `tools/eval_mapping_offline.py`，必须同时标注**语料规模 N**：
> `--universe ch23` → **N=20**（只含第 2/3 章的历史口径）；
> `--universe all` → **N=60**（课程全部启用知识点，**线上语义**，脚本默认值）。
> **`73.3%` 是 N=20 的数字，不是线上数字。** 线上语义对应 V0 `55.0%` / V2 `60.0%`。

**通道 A：字符二元组 TF-IDF（唯一打分源）**

- 语料 = `concept_text` + 知识点名称重复 3 次 + `misconception`（学生典型错因，各 1 次；
  受 `mapping.misconception-in-corpus` 控制，默认 true）。误区只追加一次，不重复——重复会变成新旋钮。
- 预处理：小写、去标点/空白/符号后切字符二元组。
- `tf = 1 + ln(count)`，`idf = (ln((N+1)/(df+1)) + 1)^1.5`，L2 归一化后余弦。
- **`df` 与 `N` 一律在课程全部启用知识点上统计**；章过滤只缩小"参与排序的候选集合"，
  不缩小统计范围（否则同一个分在不同章含义不同，阈值标尺随章漂移）。
- **排序键是原始 `cos`**，不是校准后的 `score`：`cos ≥ score-scale(0.3)` 时多个候选会饱和到
  `score = 1.0`，若按 `score` 排序就退化为按 `kpId` 字母序（单测
  `saturatedCandidatesRankByCosineNotByScore` 锁定）。
- `score = min(1, cos / mapping.score-scale)`，`application.yml` 取 0.3；`round4` 后再比阈值。
- 选型依据（**U20 口径：60 题 × 第 2—3 章 20 点语料**，同集对比）：关键词通道 48.3%、关键词+IDF 51.7%、
  字符二元组 IDF=1.0 71.7%、IDF=1.5 **73.3%（仅 20 点语料，不是线上数字）**、关键词+余弦混合 55.0%。
- 当前 V2（误区入语料）实测：

  | 口径 | top-1 | top-3 | AUTO 精确率 | 覆盖（非 FAILED） |
  | --- | --- | --- | --- | --- |
  | N=20（ch23，非线上） | 73.3% | 85.0% | 93.1% | 91.7% |
  | N=60（all，线上语义） | 60.0% | 80.0% | 91.3% | 86.7% |

  同一集上 V0（误区不入语料）为 N=20 `73.3%/81.7%`、N=60 `55.0%/73.3%`。
  **60 题样本无统计显著性**（McNemar p=0.375/0.125），只能表述为"方向一致的改善"，
  **不得**表述为显著提升。

**通道 B：关键词（仅解释，不参与排序）**

- 关键词来自 `kp_keyword`；最多展示 8 个、长度 ≥2 的命中词。
- 混合进排序会把高频词（关系/查询/SQL）权重放大，实测 top-1 降到 55.0%，故只做解释层。

**通道 C：LLM 分类（未启用）**

- 设计保留：仅在低置信时调用、只输出 JSON、结果必须在候选集内、解析失败丢弃。
- 当前未接入；接入前必须在 U60（60 题 × 60 点，线上语义）标注集上做同集对比，且不得降低 top-1。

**章先知（已实现，但当前零调用方）**

- 传 `chapterId` 时只在该章候选内排序；该章无知识点时回退全量，避免配置错误导致整单 FAILED。
- **生产调用链当前从不传 `chapterId`**：`zhixue-web/src/api/diagnosis.ts` 只发
  `{text, courseId}`，工作台没有章节选择器。因此章过滤是**零调用方死路径**，下面的数字
  **不是线上可达数字**，不得作为线上指标引用。
- 离线参考（脚本用 gold 所属章过滤，属**上限参考**，隐含"调用方传对了章"）：
  V6 在 N=20 为 `76.7%/88.3%`、N=60 为 `73.3%/86.7%`；但 V6 的 FAILED 为 9（N=20，V0 是 6）、
  15（N=60，V0 是 7），即 N=60 覆盖率只有 75.0%，**违反 ≥86.7% 的覆盖率门禁**，故不采纳。

### 1.4 决策规则与阈值校准

| 条件 | decision | 前端表现 |
| --- | --- | --- |
| `top1 ≥ 0.60` 且 `top1 - top2 ≥ 0.10` | AUTO | **预选** top1（仍允许修改） |
| `0.35 ≤ top1 < 0.60`，或领先差 `< 0.10` | CONFIRM | 下拉框高亮，**不预选**，必须人工确认 |
| `top1 < 0.35` 或无候选 | FAILED | 展示手动选择 + 按章节浏览 |

> `confirm-floor` 由 0.40 下调到 **0.35**：误区入语料后余弦整体略降，0.40 会把
> 原本正确的候选推入 FAILED。0.35 是"覆盖率不低于基线"的最小调整量。
> **前置条件**：前端只在 `decision === "AUTO"` 时预选 top1（`DiagnosisWorkbench.vue`），
> 否则低质量 CONFIRM 列表会被惯性接受。不改前端就应保留 0.40。

校准与决策分布（离线，`tools/eval_mapping_offline.py`；必须标注 N）：

**U20（60 题 × 20 点语料，历史口径）**

- V2：AUTO 29 例，精确率 93.1%；FAILED 5 例（覆盖 91.7%）。
- V0：AUTO 24 例中 23 例正确（95.8%）；分数区间 0.8—1.0 正确率 93.3%，0.4—0.6 仅 63.6%
  ——说明「低分不自动、一律转人工」的方向是对的。
- 下限敏感性（V0）：0.40 → 覆盖 86.7%、下限以上 top-1 71.2%；0.35 → 90.0% / 72.2%；
  0.30 → 覆盖 93.3%、73.2%。

**U60（60 题 × 60 点语料，线上语义）**实测：

- **合入前 main（V0，confirm-floor 0.40）**：top-1 55.0% / top-3 73.3%，AUTO 精确率 87.5%，
  覆盖 81.7%，人工率 60.0%（2026-11-03 真实后端只读重跑，
  `spark-output/qa/2026-11-03-mapping/main-u60-eval.json`）。离线 U60 V0 复算与该在线结果
  top-1/top-3 **逐位一致**，说明离线口径可迁移到生产实现。
- **V2（误区入语料 + floor 0.35）**：top-1 60.0% / top-3 80.0%，AUTO 精确率 91.3%，
  覆盖率 86.7%，人工率 61.7%。**已合入 main（2026-11-03 PM 裁决）**；合入后 top-1 +5.0pp、
  top-3 +6.7pp，人工率 +1.7pp（仍未达 ≤40% 目标，见 §6）。
- 分数区间与实际正确率（V0）：`0.0–0.4` 30%、`0.4–0.6` 36%、`0.6–0.8` 73%、`0.8–1.0` 93%。
  **中段 0.4–0.6 在大语料下几乎不再区分对错**（N=20 时该段为 63.6%），这是
  `AUTO 精确率` 成为硬约束、且中段一律留 CONFIRM 的直接依据。
- **合入后 main 在线复跑（2026-11-03 01:44）**：top-1 **34/60=56.7%** / top-3 **44/60=73.3%**，
  AUTO 精确率 90.9%，人工率 63.3%，零候选 0。此时演示库已导入第 7 章，**在线语料为 N=70**，
  离线 U60 为 N=60，两者不可直接比较；差额主因是新增 10 个知识点的干扰项，不是算法回归。
  证据：`spark-output/qa/2026-11-03-mapping/main-u70-live-eval.json`。
- **合并事实记录（2026-11-03）**：PR #3（`e9f67d5`）合并与本轮裁决“暂不合 main”不符，
  **事后接受**；理由：合并后 CI 绿（`41492667983` 五 job）且离线/在线链路一致。不回滚。
- **`confirm-floor` 配置化**：只在 `application.yml` 单点配置（代码不再写默认值）。
  演示前在线人工率 **>65%** 时，把配置改回 **0.40** 并重启；**只改配置，不回滚提交**（runbook §3.1）。
- 统计功效：60 题（每点 3 题）不足，95% Wilson 区间重叠、McNemar 均不显著（见

### 1.5 边界

- 题干为空或长度 <5：直接 FAILED，不进入打分。
- 关键词只做展示，不重复计分。
- 映射结果只作为候选，最终以学生确认的 `kp_id` 入库；映射分数写入日志供调参。
- `decision=FAILED` 不是错误码；接口仍返回 200，前端走手动选择（60003 仅用于检索无匹配）。

### 1.6 伪代码

```python
def map_kp(text, course_id, chapter_id=None):
    if len(text.strip()) < 5:
        return MapResult(decision="FAILED", candidates=[])
    cands = load_candidates(course_id)                 # 启用知识点全集（N）
    if chapter_id:                                     # 章先知：章内无点则回退全量
        scoped = [c for c in cands if c.chapter_id == chapter_id]
        cands = scoped or cands
    stats = build_stats(all_candidates)                # ★ df / N 在全量上统计，与章无关
    scored = [(c, cosine(text, c, stats)) for c in cands]
    ranked = sort_desc(scored, key="cosine", tie_break="kp_id")   # ★ 不是按 score 排
    for c, cos in ranked:
        c.score = round4(min(1.0, cos / 0.3))          # 只用于决策与展示，不参与排序
    top1, top2 = ranked[0].score, ranked[1].score if len(ranked) > 1 else 0
    decision = decide(top1, top2, auto=0.60, margin=0.10, floor=0.35)
    return MapResult(decision, ranked[0], [c for c, _ in ranked])   # 不截断：top3 语义依赖全量
```

## 2. 掌握度

### 2.1 训练事件定义（防止重复计数）

一次训练事件只属于下列之一：

1. `practice_record` 一条作答记录（对或错）；
2. `student_error_record` 一条 **CONFIRMED** 错题记录，且没有对应练习记录。

DRAFT 错题不参与计算。错题上传与练习作答不会同时写两条，服务层必须保证互斥。

**唯一入口**：学生画像、班级画像、教师端学生列表、到期复习全部调用
`MasteryAggregationService`，禁止任何 Service 再自建一套聚合；两端口径必须同一份代码。

**同日同题去重（防刷分）**：同一学生、同一题目、同一自然日只计最优 1 次——
有正确则取当天**第一次**正确（重复作答不改变当日得分与衰减权重）；同日全错只取当天最后一次错误
（错因随最后一次，不允许用更轻错因刷低惩罚）。其余重复作答不重复计权。例：同一天同一题连对 1/2/3 次，
掌握度完全相同，不再出现 `S=3 → 0.714`。

### 2.2 权重

| 错因 | key | 权重 |
| --- | --- | --- |
| 概念混淆 | CONCEPT_CONFUSION | 1.0 |
| 方法缺失 | METHOD_MISSING | 1.0 |
| 步骤遗漏 | STEP_OMISSION | 0.8 |
| 计算失误 | CALCULATION_ERROR | 0.6 |
| 边界条件 | BOUNDARY_ERROR | 0.8 |
| 未标注 / 未归类 | UNCLASSIFIED（历史 null 同） | 0.8（取中位，低于最高档） |

时间衰减：`decay(d) = 0.5^(d / 30)`，`d` 为事件距今天数；当天为 1。

### 2.3 公式

对知识点 `k`：

```
S_k = Σ decay(正确事件_i)                             // 每条正确事件按自己的时间衰减
F_k = Σ ( severity(error_type_i) * decay(错误事件_i) ) // 每条错误事件按自己的时间衰减
posterior_k = Beta(α0 + S_k, β0 + F_k)，α0=β0=2（均值 0.5 的弱先验）
mastery_k = posterior_k 均值
90% 区间 = Beta(0.05, 0.95) 分位；无新证据时 S/F 同步衰减、区间变宽并回落到 0.5
```

- 正确侧与错误侧完全对称，不允许“正确数 × decay(最后一条证据)”：最后一条证据若是今日错误，
  会把 100 天前的正确证据零衰减保留，使“以前会、最近又错”的薄弱点被系统性高估。
- 所有证据按 `(user_id, kp_id)` 分组、逐条事件衰减；教师端 SQL 的 `successWeight/severitySum`
  与学生端内存路径调用同一个 `MasteryCalculator.estimate(successWeight, failureWeight)`。
- 数字样例：100 天前 10 次全对 + 今日 1 次概念混淆 → `S≈0.992, F=1` → mean≈0.499；
  若按旧“最后证据统一衰减”会得到 Beta(12,3) mean=0.800，差 0.30。

> 旧公式 `1 - Σ严重度/N` 已废弃：只衰减错误、分母不变，长期不练会逼近 1.0。新公式冷启动/长期无证据回到先验 0.5，不逼近 1.0；`UNCLASSIFIED` 按 0.8 计，低于最高严重度。

- 全对时 mastery 随证据增加但不会等于 1（先验 β0=2 兜底）；全错时低于 0.5，长期无证据回落到 0.5。
- **预计保留率（与掌握度并列，不混为一个数）**：
  `retention_k = 0.5^(距上次正确作答天数 / half-life-days)`；从未答对记 0。
  掌握度是“当前证据下的后验均值”，长期无证据会回落到先验 0.5；保留率只看最后一次正确证据的
  遗忘程度，不会因为“停练”而升高。只用掌握度会把“弱学生停练”误读成“变好”，两个数必须同时看。
  当前仅在服务层 `MasteryAggregationService.KpMastery` 输出，尚未进入公开契约字段。
- `N_k < 3` 时仍返回原始值，但标记 `sampleCount`，前端显示"样本不足"，且不进入薄弱点排名。
- 不做跨课程聚合；所有计算按 `user_id + kp_id`。

### 2.4 五维聚合

课程维度配置存在 `course.dimension_json`（只定义 key 与展示名），每个知识点的归属以 `knowledge_point.dimension_key` 为唯一事实源（V2.1 新增列）：

```
D = Σ_{k∈dim} (N_k * mastery_k) / Σ_{k∈dim} N_k      // 仅统计 N_k ≥ 1 的知识点
```

- 若某维度所有知识点都无样本，返回 `null`，前端显示"暂无数据"，不得填 0。
- 维度得分保留 3 位小数；快照写入（**预留未启用**，见 §2.5）时落到
  `learning_portrait_snapshot.dimension_scores`，当前实时聚合路径不落库。

### 2.5 画像更新时机（实时聚合，无每日快照）

- **当前实现为实时聚合，没有每日快照任务**：`PortraitService.me()` 先读
  `learning_portrait_snapshot` 最新一行；有则用快照，没有则走 `transientPortrait(userId)`
  按练习记录与 CONFIRMED 错题实时计算（`statDate` = 当天）。
- **`learning_portrait_snapshot` 目前没有运行时写入方**（全仓无画像相关 `@Scheduled`、无插入路径；
  迁移期 `init-v2.1-migration.sql` 的一次性数据回填除外），属预留能力；启用前不得在文档/答辩中宣称"每日快照"。
- 错题确认、练习提交后不触发重算；教师班级总览 `classPortrait` 在请求内用 SQL 实时聚合
  （学生先算、再按人平均），不读取快照。
- **实时聚合时间窗**（`mastery.aggregate-window-days`，默认 180 天 = 30 天半衰 × 6）：
  教师端三个全课程聚合（学生列表 / per-kp 权重 / 错因分布）与学生画像 `transientPortrait`
  只扫窗口内记录——学期末全量历史回表（54 万行级）会被窗口挡住；窗口外证据衰减后权重
  <1.6%，丢弃不影响口径。跨学年的历史由快照承载：`me()` 快照优先已就位，快照写入方
  接入后窗口外历史即有出口。学生画像不再把练习明细拉进 JVM，全部下推聚合 SQL。
- **窗口物理收敛**：带 user 过滤的聚合（`aggregateByUserKp` 全部调用、`aggregateByUser` /
  `aggregateErrorType` 的单学生调用）在 migration `2026-11-03-diagnosis-window-index.sql`
  的 `idx_user_window (user_id, created_at, …)` 上做覆盖范围扫描：既按 180 天窗口裁剪行，
  又免回表；optimizer hint 固定该索引，避免优化器退回非覆盖的 `idx_user_time`。
  无 user 过滤的课程维度两条查询不适用该索引，仍由 `idx_q_time` 按窗口范围裁剪。
  实测（200k 行、1/3 在窗口内）：班级掌握度聚合 ≈435ms → ≈156ms。

### 2.6 边界

- 同一题在同一自然日重复作答只计最优 1 次（见 §2.1），跨天仍按各自时间独立衰减。
- 班级薄弱点的分母是**单学生样本量**：只有 `N_k >= mastery.min-samples`（默认 3）的学生进入
  该知识点的班级宏平均与错题数；全班总事件数达标但每个学生都只有 1 次时不构成薄弱点。
- 删除/停用知识点不删除历史事件，但不再出现在画像与推荐中。
- 时间使用数据库 `created_at`，不使用客户端时间，防止改系统时间刷分。

### 2.7 错因产出与归一（练习提交 / 计划打卡共用）

答错必须落五类错因之一或显式默认值 `UNCLASSIFIED`，不允许再写 `null`，
否则掌握度公式的严重度自变量为空，掌握度、推荐与实验指标都会失真。

| 场景 | 规则 |
| --- | --- |
| 答对 | `error_type = NULL`（无错因语义） |
| 客观题空答案 | `METHOD_MISSING` |
| 多选题只选中部分正确项、无干扰项 | 距上次练习 <30 天 → `STEP_OMISSION`；≥30 天 → `CONCEPT_CONFUSION` |
| 选中干扰项 | 首次作答且难度 3 → `BOUNDARY_ERROR`；其他 → `CONCEPT_CONFUSION` |
| 重复作答（≥3 次）仍错 | `METHOD_MISSING` |
| 题库答案缺失 / 其他无法归类 | `UNCLASSIFIED` |
| 主观题（填空/简答/综合） | 采用学生自评错因；未选 → `UNCLASSIFIED` |

- 客观题错因由服务端规则推断，忽略客户端 `errorType`；主观题由前端下拉选择（前端不选即 null，服务端归一）。
- 历史 `NULL`/空串记录：掌握度按 0.8 计；班级画像错因分布归入 `UNCLASSIFIED`，不丢样本。
- 规则是启发式，不声称“诊断真实心理原因”；答辩口径为“可解释的错因归类”。
- 练习提交的事务边界（05 §2.7 与 01 §8 同口径）：作答落库与推荐采纳回写
  （`recommendation.is_adopted`）在同一 `TransactionTemplate` 事务内，任一失败整体回滚；
  唯一键冲突的幂等回查发生在事务结束之后——MySQL REPEATABLE READ 下事务内回查看不到
  并发方在快照后提交的同 token 记录，放事务外才能保证并发同 token 恰落一笔。

### 2.8 作答耗时（服务端计时，进步证据数据源）

练后"进步证据"需要练习耗时，但客户端自报时间不可信（可任意伪造），因此采用服务端计时：

| 环节 | 规则 |
| --- | --- |
| 打点 | 首次打开题目时 `POST /api/practices/start`，服务端时钟写 Redis（`setIfAbsent` 首次为准，重复打点不重置），TTL 24h |
| 计时 | 提交作答带 `startToken`，`costSeconds = (提交时刻 − begin 时刻)`，由服务端计算；客户端自报 `costSeconds` 一律忽略 |
| 跨天 | 按 epoch 毫秒差计算，23:59 开始、00:01 提交 = 120 秒，恒为正，不会出现负数 |
| 超 30 分钟 | 视为挂机/离开，`costSeconds` 落 `null` 不计入统计（不截断——截断值仍是假数据） |
| 未打点 | `costSeconds` 落 `null`（缺证据时诚实留空，不用客户端自报顶替） |
| 幂等 | 重复提交返回首次记录的 `costSeconds`，不会因第二次提交变"神速"；提交成功后删除打点键，TTL 兜底 |

- 防伪造原理：时间戳全部由服务端产生并存 Redis，客户端只持有令牌——伪造令牌无记录（落 null）、
  重放打点不重置、拖后提交只会让时长变大（无收益）。剩余信任假设：Redis 与应用同机同时钟（单机部署成立）。
- 计划打卡（checkin）暂未接入打点，`source=PLAN` 的 `cost_seconds` 仍为客户端口径；
  练后进步证据统计时按 `source` 区分或仅取 SELF/RECOMMEND（由统计侧决定，落库口径已区分）。

## 3. 三层练习推荐

### 3.1 层级定义

| 层 | 目标 | 选题范围 |
| --- | --- | --- |
| CONSOLIDATE 巩固 | 同一知识点再练 | `primary_kp_id = kpId`，难度 ≤ 学生近期该点难度均值 |
| VARIANT 变式 | 换问法/换情境 | `question_kp` 关联的先修或后继 1 跳，或同章相邻知识点；难度 ±1 |
| ADVANCE 拓展 | 衔接后续内容 | `knowledge_prereq` 中 `prereq_kp_id = 当前 kp` 的后继知识点（即把当前点当先修的那些点）；难度 = min(3, 均值+1) |

### 3.2 难度匹配

- 取该生该知识点最近 5 条 `practice_record`，`avgDiff = round(mean(difficulty))`；无记录取 2。
- 巩固层 `difficulty ≤ avgDiff`；变式层 `|difficulty - avgDiff| ≤ 1`；拓展层优先 `= min(3, avgDiff+1)`，候选不足放宽为 `≥ avgDiff`。

### 3.3 去重与不足处理

1. 三层之间按 `q_id` 去重，先满足巩固层。
2. 排除当前错题对应题目、7 天内已练题目。
3. 数量不足时依次放宽：冷却 7 天 → 3 天 → 允许重复；仍不足则返回实际条数，理由改为"这章题不多，先练这几道"。
4. 持久化到 `recommendation`，唯一键 `(user_id, log_id, q_id)`；重复生成返回已有记录。

### 3.4 理由模板（学生语言，≤45 字）

理由由 §3.7 补漏评分组合生成。**目标读者是学生**，只回答"为什么练它"；
例：`这道题要用到它，已 38 天没答对，把两个概念记混了`。

**学生语言硬约束（2026-11-03 复核追加）**：默认文案禁用内部术语
（先修/权重/优先级/因子/可修复/紧迫度/补漏/聚合/后验——技术词只进本节说明层）；
术语换具体对象（直接先修 → "这道题要用到它"）；保留数字证据。

| 段 | 取值 |
| --- | --- |
| 关系 | 这道题要用到它（1 跳）/ 它是更基础的知识（2 跳）/ 你刚错的就是这块 / 学完这块，下一课就顺 / 现在练它最划算 |
| 遗忘 | 还没答对过 / 今天刚答对 / 已 N 天没答对 |
| 错因话术 | 把两个概念记混了 / 方法还没掌握 / 做题漏了步骤 / 计算上容易出错 / 特殊情况容易漏 / 错在哪再做一遍才知道（无错因时不出现） |

题量不足时整批改为 `这章题不多，先练这几道`，提示题库待补充；理由只由模板拼接，
禁止让模型自由发挥，保证可解释与可测试。上限 45 字（`recommendation.reason`）。

### 3.5 伪代码

```python
def recommend(user_id, log_id, kp_id, error_type):
    avg = recent_avg_difficulty(user_id, kp_id, limit=5) or 2
    used = practiced_qids(user_id, days=7) | {current_qid(log_id)}
    picked = []
    picked += pick_consolidate(kp_id, max_diff=avg, exclude=used, n=1)
    picked += pick_variant(kp_id, avg=avg, exclude=used | ids(picked), n=1)
    picked += pick_advance(kp_id, avg=avg, exclude=used | ids(picked), n=1)
    if len(picked) < 3:
        picked += relax_and_refill(kp_id, need=3-len(picked), exclude=ids(picked))
    save_with_unique_key(user_id, log_id, picked)
    return picked
```

### 3.6 边界

- 题库不足 3 题时允许少于 3 条，接口不报错。
- 变式层的"先修/后继"只在 `knowledge_prereq` 有数据时生效；无数据退化为同章相邻知识点。方向约定：先修 = `WHERE kp_id = 当前` 取 `prereq_kp_id`；后继 = `WHERE prereq_kp_id = 当前` 取 `kp_id`。
- 推荐不改变掌握度，只有实际作答（`practice_record`）才改变。

### 3.7 补漏排序（PRP，计划与推荐共用）

`PlanService` 与 `RecommendationService` 统一调用 `RepairPriorityService`，避免“计划按错题计数、
推荐按难度”两套口径。排序分由三因子相乘：

```
score = 先修权重 × 遗忘紧迫度 × 错因可修复性
```

| 因子 | 规则 |
| --- | --- |
| 先修权重 | 薄弱点（近阶段有错题）的 1 跳先修 1.0、2 跳先修 0.7、薄弱点自身 0.6、薄弱点直接后继 0.5、课程内其他点 0.2 |
| 遗忘紧迫度 | `1 - 0.5^(距上次正确作答天数 / mastery.half-life-days)`；有证据但**从未答对**记 1.0，**从未作答**（无任何练习/错题证据）记 0.8，当天答对记 0。两者必须区分：把“还没学”与“学了没会”都记 1.0 会让新知识点挤掉真正的漏洞。锚点取最后一次**正确**作答而非任意练习：刚答错的知识点若久无正确证据，恰是最该补的，按“距上次练习”会误判为不紧迫 |
| 错因可修复性 | 概念混淆 1.0、方法缺失 0.9、步骤遗漏 0.8、边界 0.7、计算 0.5、未归类/无错因 0.5 |

- 先修遍历只走课程内 `knowledge_prereq` 边，最多 2 跳；跨课程边不参与。
- 同分按“先修距离 → sortNo → kpId”兜底，保证多次调用顺序稳定。
- 计划生成按该排序依次取题；推荐三层先按原规则各取 1 条，再按题目所属知识点评分重排，
  理由由同一评分生成（§3.4）。
- 数据来源：`practice_record` 按知识点聚合（次数、错误数、最近练习时间、最近错因）
  **加 CONFIRMED 上传错题**（qId 已被练习覆盖的不重复计；同一题目同一自然日只取最后一次确认；
  上传错题只补“练过/答错”，不产生正确证据），与 §2.1 掌握度同口径。
  固定 4 条 SQL，不随知识点数量增加；不新增表与接口字段。

**"为什么先练它"（firstReason，算法创新评审 2026-11-03 唯一采纳项）：**

补漏重排后的第一名，由现有三因子**确定性模板拼接**生成一句话叙事（契约字段
`Recommendation.top1Reason`，**≤45 字**，仅第一条非空）——不新增模型、不调 LLM、
不改排序分数，同一输入永远同一句话（纯函数，单测锁定）。

**学生语言硬约束**（与 §3.4 同一套，实现注释同步）：目标读者是怕考试的大二学生，
只回答三件事——练哪个、为什么是它、不练会怎样；一段话不分号堆砌；禁用词
（先修/权重/优先级/因子/可修复/紧迫度/补漏/聚合/后验）只进本节说明层；
术语换具体对象；保留数字证据；禁止模型自由生成。

```
先练{知识点名}：{关系段}，{遗忘段}，{错因话术}，先练它见效最快
例：先练关系模型：这道题要用到它，已 21 天没答对，把两个概念记混了，先练它见效最快
```

与 `explain()`（§3.4 逐条简短理由）的分工：explain 给每条推荐；firstReason 只给第一名。

四种退化边界的固定文案（不编造、不猜测；反例=写成那样说明又回术语了）：

| 边界 | 正例（实现文案） | 反例（禁止） |
| --- | --- | --- |
| ① 无先修关系（distance>2 且非后继） | "先练{名}：它是你现在最没把握的一块，已 N 天没答对，先练它见效最快" | "它是当前课程中最薄弱的环节，综合先修权重最高" |
| ② 从未答对（daysSinceLastCorrect=null） | "先练{名}：你刚错的就是这块，还没答对过，方法还没掌握，先练它见效最快" | "证据不足（null），紧迫度按最高 1.0 处理" |
| ③ 错因未归类（UNCLASSIFIED/空） | "先练{名}：这道题要用到它，已 N 天没答对，错在哪再做一遍才知道，先练它见效最快" | "错因 UNCLASSIFIED，无法归类，建议人工复核" |
| ④ 冷却期内刚练过仍排第一（daysSinceLastPractice < recommend.cooldown-days） | "先练{名}：这道题要用到它，N 天前刚练过还是错，趁热再练一遍最有效" | "该知识点处于冷却期内仍排名第一，薄弱程度未消除" |

兜底：知识点无评分（不在课程范围）时返回 fallback（"先练它，见效最快"或题量不足
模板）；题量不足的整批兜底场景 top1Reason 为 null。

### 3.8 到期复习的判定与优先级（DueReviewService）

系统此前有间隔重复的“形”（半衰衰减参与掌握度与 PRP 紧迫度），但没有“到期”的实——
学生今天该复习哪几道题，没有任何机制算出来。本节补上判定、排序、选题与三种边界，
全部复用现有参数，**不另造时间常数**。

**判定（对象 = 学生 × 知识点，三条件同时满足才到期）：**

| 条件 | 规则 | 参数 |
| --- | --- | --- |
| 有正确证据 | `lastCorrectAt != null`（该点至少答对过一次） | — |
| 遗忘过半 | `距上次正确作答天数 >= mastery.half-life-days`（默认 30 天），保留率 ≤ 50% | `mastery.half-life-days` |
| 冷却外 | `距上次任意作答天数 >= recommend.cooldown-days`（默认 7 天），刚练过的不当天再推 | `recommend.cooldown-days` |

- 半衰期既是掌握度衰减参数也是到期阈值，一处定义两处复用；`recommend.cooldown-days`
  自 V2.2.4 起落进 `application.yml`，与推荐去重（§3.3）、计划排题冷却共用同一配置
  （推荐内部的 3 天放宽档是固定梯度，不随该值缩放）。
- 时间口径与 PRP 一致：`Duration.between(...).toDays()` 满 24 小时计数，`Asia/Shanghai`。

**排序（到期项内部）：**

```
score = 遗忘紧迫度 × (1 - 掌握度)
遗忘紧迫度 = 1 - 0.5^(距上次正确作答天数 / half-life-days)   // 与 §3.7 同式
```

- 掌握度与画像同源（`PortraitService.userKpAggregates`：练习窗口聚合 + 无练习覆盖的
  CONFIRMED 错题补事件，`mastery.aggregate-window-days` 窗口外无证据按 Beta(2,2) 先验 0.5），
  学生看到的画像数字与到期排序里的掌握度不能两处口径。
- 同分按 sortNo → kpId 兜底；每日队列上限 5 项（与画像薄弱点 WEAK_LIMIT 一致的日消化量）。

**选题（建议重做的题）：** 优先重做该知识点**最近答错**的题（最值得重测），其次最近答对
的题（同题重测保留率）；练过的题已不在题库时用该点未练过的题兜底（难度升序）；无可用
题目则跳过并记 warn（内容缺口）。到期知识点自身的练习必然在冷却外（kp 级冷却已挡），
无需再做题级冷却。

**理由模板（学生语言，≤45 字，禁止自由发挥）：**
`距上次答对 N 天，早该复习了` + 答错过时 `，{错因话术}`（复用 §3.4 错因话术表），
只对过时 `，该回来练一遍`。例：`距上次答对 40 天，早该复习了，把两个概念记混了`。

**三种边界（答辩必考）：**

| 边界 | 处理 | 理由 |
| --- | --- | --- |
| 没做过题的学生 | 到期队列为空，走首次使用引导/新知识推进 | 没有练习信号就没有“上次作答时间”，不造默认复习项 |
| 只做对过的学生 | 距上次答对 ≥ 半衰期的点**照样到期**（理由为"该回来练一遍"） | 保留率随时间衰减是独立事实，掌握度高只影响排序不豁免——只对过≠永远不用复习 |
| 错题但刚复习过的学生（上次练习 < 冷却 7 天） | 冷却内不出队 | 刚复习过说明节奏正在执行，重复推送会挤掉别的到期项；7 天后若仍未重新答对，`lastCorrectAt` 未刷新，自然回到队首 |

补充第四条隐含边界：**从未答对但错过**的点不进到期队列——那不是“复习”是“补漏”，由
PRP（§3.7）锚点覆盖；两套机制分工：PRP 管“现在薄弱”，到期复习管“曾经会、正在忘”。

**复习完成的回执就是练习记录本身：** 作答刷新 `lastPracticedAt`（冷却重新计时）与
`lastCorrectAt`（若答对，半衰重新计时），下一次到期由同一判定自然给出——无新增状态表、
无“复习已读”标记，队列是练习信号的纯函数。

**今日任务三来源优先级：**

| 序 | 来源 | 内容 | 说明 |
| --- | --- | --- | --- |
| 1 | 到期复习（DUE_REVIEW） | 本节队列 | 时间驱动的事实，不练就持续贬值；前端把到期复习卡排在计划/推荐之前，**不被新题挤掉** |
| 2 | 薄弱补漏（PRP） | 今日计划题、CONSOLIDATE/VARIANT 推荐层 | 错题驱动的当前短板（§3.7） |
| 3 | 新知识推进 | ADVANCE 推荐层、计划覆盖的未练知识点 | 衔接后续内容 |

**数据来源：** 固定 4 条 SQL（知识点、kp 信号、题目信号、课程题库），不随知识点数量增长；
不新增表。`kp 信号`在 §3.7 的 3 条 SQL 上加 `MAX(created_at) AS lastPracticedAt` 一列
（PRP 忽略该列，互不影响）。

## 4. 检索与讲解

### 4.1 语料与切片

| 来源 | 说明 |
| --- | --- |
| `knowledge_point.concept_text` | 每点 300–500 字，至少 1 个切片 |
| 教材切片（P4 补） | 按段落切，保留 `kp_id` 与页码 |
| `misconception` | 不作为检索语料，只进 L3 模板与 Prompt 误区段 |

切片规则：按段落优先、句子次之；目标 300–500 字，重叠 50 字；切片 ID 为 `kpId#序号`。

### 4.2 混合检索

```
vec_score = cosine( query_emb, chunk_emb )          // bge-small-zh-v1.5，归一化
kw_score  = min(1, bm25(query, chunk) / bm25(query, query))   // 字符二元组 BM25；比值可能 >1，min 截断，排序不变
w         = 0.7（bge 模式） / 0.15（hash 模式）
final     = w * vec_score + (1 - w) * kw_score
```

- 关键词通道用 BM25（k1=1.2, b=0.75：tf 饱和 + 文档长度归一），查询自评分归一到 0—1；
  分词前去掉标点/符号/空白，避免「，」「（」这类高频符号进入词表稀释实词权重。
- 60 题检索评测（`zhixue-ai/tools/eval_retrieval.py`：题干作查询、gold 知识点切片作目标）：
  recall@5 70.0%→88.3%，MRR@5 0.550→0.749，知识点 top-1 46.7%→68.3%；
  默认阈值下 top-5 含 gold 58.3%→78.3%，过阈但 gold 不在 32.7%→11.3%。
- 先按 `course_id`、可选 `chapter_id`、`kp_id` 过滤，再算分（避坑 R1）。
- 取 topK=5；bge 模式最高分 < 0.35、hash 模式 < 0.10 时返回 `60003`，不把无关切片塞进 Prompt。
- 200 条切片规模下用 numpy 矩阵一次点积，毫秒级；超过 1 万条再换 hnswlib。

### 4.2.1 检索能力边界与答辩口径（2026-11-03 实测）

**评测口径：** 主库 81 个知识点、89 个切片，`hash-bigram + BM25`；查询为
`zhixue-ai/tools/testdata/queries_student_style.json` 中 32 条人工构造的学生式提问，
四类各 8 条，不是真实试用采集。本地逐条明细（按忽略规则不入库，可复跑生成）见
`zhixue-ai/data/rag_index_report.json`。
本集与 §4.2 的 60 道题干集在样本、用途和索引范围上不同，**两组数字不得直接比较或互相替换**。

| 指标 | 本次结果 | 能力边界 |
| --- | --- | --- |
| `recall@5`（`threshold=0`，只评排序） | **32/32 = 100%** | 可用于辅助展示候选知识点、教材切片和页码来源；不等于语义理解 100%，也不代表讲解质量 |
| 知识点 `top1`（同上） | **23/32 = 71.88%** | **不作为自动答案来源**；只能作为候选排序，需由学生或教师确认，不能直接生成“系统认定答案” |
| 生产默认阈值 | top-5 含 gold 30/32；空返回 2/32 | 低分时不注入无关上下文，宁缺毋滥 |

**界面口径：** 检索结果只能称“候选知识点”“教材依据”或“参考资料”，不得称
“推荐答案”“自动答案”或“标准答案”。题库中经内容复核的“参考答案”是题目数据，
与 RAG `top1` 不是同一概念，二者不得混用。

**默认阈值下两例空返回（这是设计，不是故障）：**

| 查询 | gold 知识点 | 处理口径 |
| --- | --- | --- |
| S-Q02：先筛选成绩及格学生，再保留学号和姓名，问两种关系运算 | `KP0210` | 分数未过阈值，返回空 `sources`，拒绝把低置信度切片注入 Prompt |
| S-E04：删除学生时仍有选课引用，问级联删除策略 | `KP0504` | 同上；不是崩溃、超时或服务不可用，不得为演示把阈值偷偷降到 0 |

排障时必须区分“健康服务主动返回空结果”与“5xx/超时/连接失败”。前者按上述设计解释，
后者才按故障处理。

**答辩统一口径（可直接照读）：**

> 我们的 RAG 用于辅助检索教材切片和展示来源，不用于自动决定答案。在 81 个知识点、
> 89 个切片的当前索引上，32 条人工学生式查询的 top5 召回是 100%，所以可用于候选资料展示；
> 但 top1 只有 71.88%，我们不把它当作自动答案来源。默认阈值下有两条查询没有足够证据，
> 系统主动返回空结果，避免把无关内容交给模型，这是宁缺毋滥的设计，不是故障。
> 该评测是小规模回归测试，不是对真实试用效果的宣称。

**索引生命周期与答辩现场要求：** `data/vector_index/` 是本地生成产物，新环境、重建演示库或
更新 `concept_text` 后必须按 `zhixue-ai/README.md` 重建。索引文件由 AI 进程在首次检索或嵌入时
懒加载并常驻内存，不会监听文件热更新。**替换磁盘索引文件、由另一进程重建或合并更新后，
必须重启 AI 服务**；通过当前进程的 `/api/rag/embed` 重建会同步更新该进程内存，但答辩现场仍统一
执行“**重建索引后必须重启 AI 服务**”，再抽查 `KP0810` 等新知识点的检索与页码来源，避免把旧进程、
旧目录或旧内存带到现场。只重启 Java 或前端无效。

### 4.3 Prompt 约束

- 系统约束：只允许使用给定切片；不足时回答"资料不足，建议查阅教材第 X 页"；禁止编造页码。
- 输出结构固定：思路点拨 → 关键步骤 → 常见误区 → 自检提示 → 来源列表。
- 温度 0.3；最大 800 token；同一请求缓存命中直接回放。
- 生成后校验：正文至少包含 1 个 `[KPxxxx·教材Pxx]` 引用，否则在末尾补来源块；溯源率按"有引用讲解数 / 总讲解数"统计。

### 4.4 四级降级

| 级别 | 条件 | 输出 |
| --- | --- | --- |
| L1 | 默认 | DeepSeek-V3 正常生成 |
| L2 | L1 超时/5xx/限流，重试 1 次失败 | GLM-4-Flash |
| L3 | L1/L2 均失败或断网 | 模板（见下） |
| L4 | L3 所需 `concept_text` 缺失 | `60001` |

L3 模板（不依赖网络）：

```
【概念】{concept_text 前 120 字}
【这道题错在哪】{该错因对应的误区条目}
【正确思路】① 定位知识点 ② 对照概念找偏差 ③ 按步骤重做
【自检】{trial_hint}
来源：[{kp_id}·教材{textbook_page}]
```

### 4.5 合规拦截

- 规则层：正则 + 关键词（代写、直接给答案、考试作弊、帮我写作业）。
- 灰区（P1 增强）：LLM 意图二分类，仅在高相似度时调用。
- 命中后返回 `60004` 或 `blockFlag=true` 的提示文本，不生成讲解；写 `ai_generation_log.is_blocked=1`。

### 4.6 评阅回流学生端（复核标记）

教师评阅此前只作用于教师后台（能看、能 PASS/RETURN、能写评语），学生端完全无感——
评阅对学习行为不起作用。本节定义回流口径：**拉取式**（学生下次打开这条记录时看到状态），
不做通知、不做站内信（本期已砍掉通知功能）。

**回流出口（三处，均为已有端点的字段扩展，不新增端点）：**

| 出口 | 字段 | 语义 |
| --- | --- | --- |
| `GET /api/error/records`（列表） | `reviewResult/reviewComment/reviewedAt` | 该错题的复核状态（聚合，见下） |
| `GET /api/error/records/{id}`（详情） | 同上 | 同上 |
| `GET /api/diagnosis/explain/{explainId}`（讲解查询） | 同上 | **该讲解自身**的评阅状态，不聚合 |

**聚合口径：** 错题的复核状态 = 该错题（`log_id`）下**最新一条已评阅讲解**
（`scene='RAG'` 且 `reviewed_at` 非空，按 `reviewed_at` 取最大，同刻按 `log_pk` 兜底）的
`review_result/teacher_comment/reviewed_at`。一条错题可能多次生成讲解（缓存回放/重新
生成各落一行），评阅对象是讲解而非错题，因此取最新已评阅的一条。

**口径诚实（答辩必考）：**

- `reviewResult` 只表示"**教师看过该讲解并给出结论**"——PASS 不等于答案正确，
  不得在前端渲染为"你的答案已确认正确"；建议文案：PASS → "已复核（通过）"，
  RETURN → "已退回补充"。
- `teacherComment` 在 PASS 与 RETURN 下都回流学生端（PASS 可为空，有评语则原样展示）；
  `teacherScore`（1—5）**不回流学生端**：它评的是讲解质量（G7 教师抽检/双评候选数据源，G7 当前仅文档），
  回流会被误读为"老师给我打的分"。
- RETURN 必带评语（教师端 40900/40000 校验），学生端展示评语即"下一步该做什么"的依据；
  指引文案（如"按老师意见修正理解后，可在错题本重做该题或重新生成讲解"）由前端固定
  模板渲染，不由后端生成。

**四种边界：**

| 边界 | 处理 | 理由 |
| --- | --- | --- |
| ① 未评阅 | 三字段返回 null，前端不显示复核标记（或显示"讲解待复核"） | 没有"教师已看"的事实就不制造标记 |
| ② 评阅后学生又重做 | 复核标记**保持不变** | 复核是对讲解的结论，与练习行为正交；重写 `practice_record` 不触碰 `ai_generation_log` |
| ③ 教师退回后学生补充再提交（重新生成讲解） | 旧 RETURN 意见**不清退**，持续可见；新讲解被评阅后自动更新为新结论 | 聚合只看已评阅讲解——退回意见在教师评阅新讲解前仍是学生能看到的最新教师反馈；直接清退会让学生错过"该做什么" |
| ④ 教师改了评阅结论（PASS→RETURN） | 当前状态机评阅**一经提交不可改**（重复评阅 40900），此场景 API 不可达；学生端每次**实时读库不缓存**，若未来放开改评，最新结论自然可见，无旧状态残留 | 不变式优先于可变性：不可改 + 实时读 = 结构性无旧状态 |

**实现要点：** 聚合查询 `selectReviewedByUserAndLogIds`（user_id + scene + reviewed_at 非空 +
有界 `log_id IN`（列表页 ≤50），走 `idx_user_time`/`idx_pending_review`），Java 侧按 logId
分组取最新，一次批量不逐条 N+1；错题列表/详情每次请求实时查库，无缓存、无冗余状态列、
不新增表。
