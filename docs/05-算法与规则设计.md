## 1. 知识点映射

### 1.1 输入与输出

输入：题干文本（OCR 校正后）、`courseId`、可选 `chapterId`。
输出：`decision`（AUTO / CONFIRM / FAILED）、`top1`、候选列表（含分数与命中通道）。

### 1.2 预处理

1. 全角转半角，统一小写，保留 SQL 关键字与符号（`SELECT`、`主键`、`FK`）。
2. 去掉题号、"选择题"等无信息前缀。
3. 按课程过滤候选集；若传 `chapterId`，只保留该章知识点。

### 1.3 打分通道（当前实现口径）

**通道 A：字符二元组 TF-IDF（唯一打分源）**

- 语料 = `concept_text` + 知识点名称重复 3 次；小写、去标点/空白/符号后切字符二元组。
- `tf = 1 + ln(count)`，`idf = (ln((N+1)/(df+1)) + 1)^1.5`，L2 归一化后余弦。
- `score = min(1, cos / mapping.score-scale)`，`application.yml` 取 0.3。
- 选型依据（**U20 口径：60 题 × 第 2—3 章 20 点语料**，同集对比）：关键词通道 48.3%、关键词+IDF 51.7%、
  字符二元组 IDF=1.0 71.7%、IDF=1.5 **73.3%（仅 20 点语料，不是线上数字）**、关键词+余弦混合 55.0%。

**通道 B：关键词（仅解释，不参与排序）**

- 关键词来自 `kp_keyword`；最多展示 8 个、长度 ≥2 的命中词。
- 混合进排序会把高频词（关系/查询/SQL）权重放大，实测 top-1 降到 55.0%，故只做解释层。

**通道 C：LLM 分类（未启用）**

- 设计保留：仅在低置信时调用、只输出 JSON、结果必须在候选集内、解析失败丢弃。
- 当前未接入；接入前必须在 U60（60 题 × 60 点，线上语义）标注集上做同集对比，且不得降低 top-1。

**章先知**

- 传 `chapterId` 时只在该章候选内排序；该章无知识点时回退全量，避免配置错误导致整单 FAILED。
- **该分支为零调用方死路径**：前端 `diagnosis.ts` 与控制器均不传 `chapterId`，生产不可达。
  因此旧的「传 chapterId top-1 76.7% / top-3 88.3%」**不得作为线上指标引用**；离线留档与
  覆盖率代价见 `tools/testdata/MAPPING_EVAL_STATUS.md`（分支 `ai/mapping-eval-20261103`）。

### 1.4 决策规则与阈值校准

| 条件 | decision | 前端表现 |
| --- | --- | --- |
| `top1 ≥ 0.60` 且 `top1 - top2 ≥ 0.10` | AUTO | 预填知识点，仍允许修改 |
| `0.40 ≤ top1 < 0.60`，或领先差 `< 0.10` | CONFIRM | 下拉框高亮，必须人工确认 |
| `top1 < 0.40` 或无候选 | FAILED | 展示手动选择 + 按章节浏览 |

**U20（60 题 × 20 点语料，历史口径）**校准结果：

- AUTO 24 例中 23 例正确（95.8%）；分数区间 0.8—1.0 正确率 93.3%，0.4—0.6 仅 63.6%——说明
  「低分不自动、一律转人工」的方向是对的。
- 下限敏感性：0.40 → 覆盖 86.7%、下限以上 top-1 71.2%；0.30 → 覆盖 93.3%、73.2%。
  `mapping.confirm-floor` 目前保持 0.40，未按此建议上线调参。

**U60（60 题 × 60 点语料，线上语义）**实测：
**main 当前（V0，confirm-floor 0.40）：top-1 55.0% / top-3 73.3%，AUTO 精确率 87.5%，
覆盖 81.7%，人工率 60.0%**（2026-11-03 真实后端只读重跑，`spark-output/qa/2026-11-03-mapping/main-u60-eval.json`）。
候选 V2（误区入语料 + floor 0.35，分支 `ai/mapping-eval-20261103` **未合入**）：
top-1 60.0% / top-3 80.0%，AUTO 精确率 91.3%，覆盖率 86.7%，人工率 61.7%。
两口径 top-1 差 5.0pp、top-3 差 6.7pp；是否合入待 PM 裁决。

### 1.5 边界

- 题干为空或长度 <5：直接 FAILED，不进入打分。
- 关键词只做展示，不重复计分。
- 映射结果只作为候选，最终以学生确认的 `kp_id` 入库；映射分数写入日志供调参。
- `decision=FAILED` 不是错误码；接口仍返回 200，前端走手动选择（60003 仅用于检索无匹配）。

### 1.6 伪代码

```python
def map_kp(text, course_id, chapter_id=None):
    if len(text.strip()) < 5:
        return MapResult(decision="FAILED", candidates=[])
    cands = load_candidates(course_id)                 # 启用知识点全集
    if chapter_id:                                     # 章先知：章内无点则回退全量
        scoped = [c for c in cands if c.chapter_id == chapter_id]
        cands = scoped or cands
    scores = {c.kp_id: tfidf_cosine(text, c) / 0.3 for c in cands}   # 截断到 1
    ranked = sort_desc(scores, tie_break="kp_id")
    top1, top2 = ranked[0], ranked[1] if len(ranked) > 1 else 0
    decision = decide(top1, top2, auto=0.60, margin=0.10, floor=0.40)
    return MapResult(decision, top1, ranked[:5])
```

## 2. 掌握度

### 2.1 训练事件定义（防止重复计数）

一次训练事件只属于下列之一：

1. `practice_record` 一条作答记录（对或错）；
2. `student_error_record` 一条 **CONFIRMED** 错题记录，且没有对应练习记录。

DRAFT 错题不参与计算。错题上传与练习作答不会同时写两条，服务层必须保证互斥。

### 2.2 权重

| 错因 | key | 权重 |
| --- | --- | --- |
| 概念混淆 | CONCEPT_CONFUSION | 1.0 |
| 方法缺失 | METHOD_MISSING | 1.0 |
| 步骤遗漏 | STEP_OMISSION | 0.8 |
| 计算失误 | CALCULATION_ERROR | 0.6 |
| 边界条件 | BOUNDARY_ERROR | 0.8 |
| 未标注 / 未归类 | UNCLASSIFIED（历史 null 同） | 0.8（取中位，低于最高档） |

时间衰减：`decay(d) = 0.5^(d / 30)`，`d` 为事件距今天数；当天为 1。

### 2.3 公式

对知识点 `k`：

```
S_k = 正确事件数 × decay(最后一次证据)
F_k = Σ ( severity(error_type_i) * decay(d_i) )      // 只累加错误事件，但正确事件也衰减
posterior_k = Beta(α0 + S_k, β0 + F_k)，α0=β0=2（均值 0.5 的弱先验）
mastery_k = posterior_k 均值
90% 区间 = Beta(0.05, 0.95) 分位；无新证据时 S/F 同步衰减、区间变宽并回落到 0.5
```

> 旧公式 `1 - Σ严重度/N` 已废弃：只衰减错误、分母不变，长期不练会逼近 1.0。新公式冷启动/长期无证据回到先验 0.5，不逼近 1.0；`UNCLASSIFIED` 按 0.8 计，低于最高严重度。

- 全对时 mastery 随证据增加但不会等于 1（先验 β0=2 兜底）；全错时低于 0.5，长期无证据回落到 0.5。
- `N_k < 3` 时仍返回原始值，但标记 `sampleCount`，前端显示"样本不足"，且不进入薄弱点排名。
- 不做跨课程聚合；所有计算按 `user_id + kp_id`。

### 2.4 五维聚合

课程维度配置存在 `course.dimension_json`（只定义 key 与展示名），每个知识点的归属以 `knowledge_point.dimension_key` 为唯一事实源（V2.1 新增列）：

```
D = Σ_{k∈dim} (N_k * mastery_k) / Σ_{k∈dim} N_k      // 仅统计 N_k ≥ 1 的知识点
```

- 若某维度所有知识点都无样本，返回 `null`，前端显示"暂无数据"，不得填 0。
- 维度得分保留 3 位小数，写入 `learning_portrait_snapshot.dimension_scores`。

### 2.5 快照与更新时机

- 每日 02:00 定时任务为活跃学生（近 7 天有事件）生成快照。
- 错题确认、练习提交后只标记 dirty，不在请求线程内重算，避免接口变慢。
- 教师班级总览读取最近快照，不在请求内实时聚合 15 个学生。

### 2.6 边界

- 同一题重复做错多次，每次都是独立事件并各自计衰减。
- 删除/停用知识点不删除历史事件，但不再出现在画像与推荐中。
- 时间使用数据库 `created_at`，不使用客户端时间，防止改系统时间刷分。

### 2.7 错因产出与归一（练习提交 / 计划打卡共用）

答错必须落五类错因之一或显式默认值 `UNCLASSIFIED`，不允许再写 `null`，
否则掌握度公式的严重度自变量为空，掌握度、推荐与实验指标都会失真。

| 场景 | 规则 |
| --- | --- |
| 答对 | `error_type = NULL`（无错因语义） |
| 客观题空答案 | `METHOD_MISSING` |
| 多选题只选中部分正确项、无干扰项 | 距上次练习 <30 天 → `STEP_OMISSION`；≥30 天 → `CONCEPT_CONFUSION` |
| 选中干扰项 | 首次作答且难度 3 → `BOUNDARY_ERROR`；其他 → `CONCEPT_CONFUSION` |
| 重复作答（≥3 次）仍错 | `METHOD_MISSING` |
| 题库答案缺失 / 其他无法归类 | `UNCLASSIFIED` |
| 主观题（填空/简答/综合） | 采用学生自评错因；未选 → `UNCLASSIFIED` |

- 客观题错因由服务端规则推断，忽略客户端 `errorType`；主观题由前端下拉选择（前端不选即 null，服务端归一）。
- 历史 `NULL`/空串记录：掌握度按 0.8 计；班级画像错因分布归入 `UNCLASSIFIED`，不丢样本。
- 规则是启发式，不声称“诊断真实心理原因”；答辩口径为“可解释的错因归类”。

## 3. 三层练习推荐

### 3.1 层级定义

| 层 | 目标 | 选题范围 |
| --- | --- | --- |
| CONSOLIDATE 巩固 | 同一知识点再练 | `primary_kp_id = kpId`，难度 ≤ 学生近期该点难度均值 |
| VARIANT 变式 | 换问法/换情境 | `question_kp` 关联的先修或后继 1 跳，或同章相邻知识点；难度 ±1 |
| ADVANCE 拓展 | 衔接后续内容 | `knowledge_prereq` 中 `prereq_kp_id = 当前 kp` 的后继知识点（即把当前点当先修的那些点）；难度 = min(3, 均值+1) |

### 3.2 难度匹配

- 取该生该知识点最近 5 条 `practice_record`，`avgDiff = round(mean(difficulty))`；无记录取 2。
- 巩固层 `difficulty ≤ avgDiff`；变式层 `|difficulty - avgDiff| ≤ 1`；拓展层优先 `= min(3, avgDiff+1)`，候选不足放宽为 `≥ avgDiff`。

### 3.3 去重与不足处理

1. 三层之间按 `q_id` 去重，先满足巩固层。
2. 排除当前错题对应题目、7 天内已练题目。
3. 数量不足时依次放宽：冷却 7 天 → 3 天 → 允许重复；仍不足则返回实际条数，理由改为"题量不足，先练这些"。
4. 持久化到 `recommendation`，唯一键 `(user_id, log_id, q_id)`；重复生成返回已有记录。

### 3.4 理由模板（≤50 字）

理由由 §3.7 补漏评分组合生成，三段式：**关系 + 遗忘紧迫度 + 最近错因**，
例：`前置知识点未掌握 + 距上次练习 38 天 + 概念混淆型错误`。

| 段 | 取值 |
| --- | --- |
| 关系 | 前置知识点未掌握（1 跳）/ 二级前置未掌握（2 跳）/ 当前知识点未掌握 / 衔接后继知识点 / 常规巩固 |
| 紧迫度 | 尚未练习 / 今日已练习 / 距上次练习 N 天 |
| 错因 | 概念混淆、方法缺失、步骤遗漏、计算错误、边界错误、错因未归类（无错因时不出现） |

题量不足时整批改为 `题量不足，先练这些`，提示题库待补充；理由只由模板拼接，
禁止让模型自由发挥，保证可解释与可测试。上限 50 字与 `recommendation.reason` 列一致。

### 3.5 伪代码

```python
def recommend(user_id, log_id, kp_id, error_type):
    avg = recent_avg_difficulty(user_id, kp_id, limit=5) or 2
    used = practiced_qids(user_id, days=7) | {current_qid(log_id)}
    picked = []
    picked += pick_consolidate(kp_id, max_diff=avg, exclude=used, n=1)
    picked += pick_variant(kp_id, avg=avg, exclude=used | ids(picked), n=1)
    picked += pick_advance(kp_id, avg=avg, exclude=used | ids(picked), n=1)
    if len(picked) < 3:
        picked += relax_and_refill(kp_id, need=3-len(picked), exclude=ids(picked))
    save_with_unique_key(user_id, log_id, picked)
    return picked
```

### 3.6 边界

- 题库不足 3 题时允许少于 3 条，接口不报错。
- 变式层的"先修/后继"只在 `knowledge_prereq` 有数据时生效；无数据退化为同章相邻知识点。方向约定：先修 = `WHERE kp_id = 当前` 取 `prereq_kp_id`；后继 = `WHERE prereq_kp_id = 当前` 取 `kp_id`。
- 推荐不改变掌握度，只有实际作答（`practice_record`）才改变。

### 3.7 补漏排序（PRP，计划与推荐共用）

`PlanService` 与 `RecommendationService` 统一调用 `RepairPriorityService`，避免“计划按错题计数、
推荐按难度”两套口径。排序分由三因子相乘：

```
score = 先修权重 × 遗忘紧迫度 × 错因可修复性
```

| 因子 | 规则 |
| --- | --- |
| 先修权重 | 薄弱点（近阶段有错题）的 1 跳先修 1.0、2 跳先修 0.7、薄弱点自身 0.6、薄弱点直接后继 0.5、课程内其他点 0.2 |
| 遗忘紧迫度 | `1 - 0.5^(距上次练习天数 / mastery.half-life-days)`；从未练习记 1.0，当天练习记 0 |
| 错因可修复性 | 概念混淆 1.0、方法缺失 0.9、步骤遗漏 0.8、边界 0.7、计算 0.5、未归类/无错因 0.5 |

- 先修遍历只走课程内 `knowledge_prereq` 边，最多 2 跳；跨课程边不参与。
- 同分按“先修距离 → sortNo → kpId”兜底，保证多次调用顺序稳定。
- 计划生成按该排序依次取题；推荐三层先按原规则各取 1 条，再按题目所属知识点评分重排，
  理由由同一评分生成（§3.4）。
- 数据来源：`practice_record` 按知识点聚合（次数、错误数、最近练习时间、最近错因），
  固定 3 条 SQL，不随知识点数量增加；不新增表与接口字段。

## 4. 检索与讲解

### 4.1 语料与切片

| 来源 | 说明 |
| --- | --- |
| `knowledge_point.concept_text` | 每点 300–500 字，至少 1 个切片 |
| 教材切片（P4 补） | 按段落切，保留 `kp_id` 与页码 |
| `misconception` | 不作为检索语料，只进 L3 模板与 Prompt 误区段 |

切片规则：按段落优先、句子次之；目标 300–500 字，重叠 50 字；切片 ID 为 `kpId#序号`。

### 4.2 混合检索

```
vec_score = cosine( query_emb, chunk_emb )          // bge-small-zh-v1.5，归一化
kw_score  = min(1, bm25(query, chunk) / bm25(query, query))   // 字符二元组 BM25；比值可能 >1，min 截断，排序不变
w         = 0.7（bge 模式） / 0.15（hash 模式）
final     = w * vec_score + (1 - w) * kw_score
```

- 关键词通道用 BM25（k1=1.2, b=0.75：tf 饱和 + 文档长度归一），查询自评分归一到 0—1；
  分词前去掉标点/符号/空白，避免「，」「（」这类高频符号进入词表稀释实词权重。
- 60 题检索评测（`zhixue-ai/tools/eval_retrieval.py`：题干作查询、gold 知识点切片作目标）：
  recall@5 70.0%→88.3%，MRR@5 0.550→0.749，知识点 top-1 46.7%→68.3%；
  默认阈值下 top-5 含 gold 58.3%→78.3%，过阈但 gold 不在 32.7%→11.3%。
- 先按 `course_id`、可选 `chapter_id`、`kp_id` 过滤，再算分（避坑 R1）。
- 取 topK=5；bge 模式最高分 < 0.35、hash 模式 < 0.10 时返回 `60003`，不把无关切片塞进 Prompt。
- 200 条切片规模下用 numpy 矩阵一次点积，毫秒级；超过 1 万条再换 hnswlib。

### 4.3 Prompt 约束

- 系统约束：只允许使用给定切片；不足时回答"资料不足，建议查阅教材第 X 页"；禁止编造页码。
- 输出结构固定：思路点拨 → 关键步骤 → 常见误区 → 自检提示 → 来源列表。
- 温度 0.3；最大 800 token；同一请求缓存命中直接回放。
- 生成后校验：正文至少包含 1 个 `[KPxxxx·教材Pxx]` 引用，否则在末尾补来源块；溯源率按"有引用讲解数 / 总讲解数"统计。

### 4.4 四级降级

| 级别 | 条件 | 输出 |
| --- | --- | --- |
| L1 | 默认 | DeepSeek-V3 正常生成 |
| L2 | L1 超时/5xx/限流，重试 1 次失败 | GLM-4-Flash |
| L3 | L1/L2 均失败或断网 | 模板（见下） |
| L4 | L3 所需 `concept_text` 缺失 | `60001` |

L3 模板（不依赖网络）：

```
【概念】{concept_text 前 120 字}
【这道题错在哪】{该错因对应的误区条目}
【正确思路】① 定位知识点 ② 对照概念找偏差 ③ 按步骤重做
【自检】{trial_hint}
来源：[{kp_id}·教材{textbook_page}]
```

### 4.5 合规拦截

- 规则层：正则 + 关键词（代写、直接给答案、考试作弊、帮我写作业）。
- 灰区（P1 增强）：LLM 意图二分类，仅在高相似度时调用。
- 命中后返回 `60004` 或 `blockFlag=true` 的提示文本，不生成讲解；写 `ai_generation_log.is_blocked=1`。

> **人工率口径（2026-11-03）**：当前 main U60 **60.0%**、候选 V2 **61.7%**、U20 V2 **51.7%**，**均未达 ≤40% 目标**；
> 任何答辩/合规/软著材料不得把 61.7% 写成达标。目标不降，改进路径：
> ① `confirm-floor` 在标注集上做敏感性（只评估、不动线上默认 0.40）；
> ② 误区入语料（V2 已把 U60 top-3 提到 80.0%，但人工率未降）；
> ③ 教师确认回流——把评阅结果回填标注集，扩样后重评。三者均需另开任务包，不在本轮上线。

调参只允许在标注集上做，禁止用试用学生数据反复调阈值；参数变更记录在本文第 0 节表格下方追加日期。
