## 1. 前置

- MySQL 8.x、Redis 7.x；Docker 可选。
- JDK 21、Maven 3.9+、Python 3.12（只跑后端/前端/RAG 时需要）。
- 本机 MySQL 的 `mysql.exe` 默认在
  `C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe`；不在 PATH 时用 `-MySqlExe` 指定。

## 2. 方式 A：Docker（推荐全新机器）

```powershell
cd zhixue
docker compose up -d
docker compose ps
```

`docker-compose.yml` 已挂载下列文件，MySQL 首次初始化时按文件名顺序执行：

```
01-init-v2.sql
02-seed-kp-ch01.sql        第1章 10 点
03-seed-question-ch01.sql  第1章 25 题
04-seed-kp-ch02-ch03.sql   第2—3章 20 点
05-seed-question-ch02-ch03.sql  第2—3章 60 题
06-seed-kp-ch04.sql        第4章 11 点
07-seed-question-ch04.sql  第4章 26 题
08-seed-prereq-ch01.sql    第1章先修边（含跨章边，放在所有知识点之后）
09-seed-prereq-ch04.sql    第4章先修边
10-seed-demo-users.sql     演示账号
11-seed-demo-data.sql      演示练习/错题/评阅
```

注意：

- **已有 `data/mysql` 时 initdb 不会重跑**。要重新灌，先确认没有要保留的数据，
  备份后删除 `data/mysql`，再 `docker compose down && docker compose up -d`。
- 生产/真实试用环境不要执行 `10-seed-demo-users.sql`（固定演示口令）。

## 3. 方式 B：本机 MySQL（无 Docker）

```powershell
cd zhixue
$env:DB_PASSWORD = '<本机 root 口令>'
pwsh -ExecutionPolicy Bypass -File .\scripts\seed-demo.ps1
```

- 默认库名 `zhixue`，与后端 `application-dev.yml` 一致；脚本只做 upsert，不删库。
- 需要从零重建：追加 `-Recreate -Force`（只删除 `-Database` 指定的库）。
- 不碰现有 `zhixue` 库的演练：

```powershell
pwsh -ExecutionPolicy Bypass -File .\scripts\seed-demo.ps1 `
  -Database zhixue_demo -Recreate -Force -Password '<本机 root 口令>'
```

启动后端时用环境变量指过去：

```powershell
$env:SPRING_DATASOURCE_URL = 'jdbc:mysql://127.0.0.1:3306/zhixue_demo?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true'
$env:DB_PASSWORD = '<本机 root 口令>'
java -jar zhixue-server\zhixue-bootstrap\target\zhixue-bootstrap-0.1.0-SNAPSHOT.jar
```

脚本末尾会打印 `chapter / knowledge_point / question_bank / sys_user / practice_record /
student_error_record / ai_generation_log / pending_review` 八项计数，便于现场核对。

## 6. RAG 索引

演示库重建后，必须重新为 41 个知识点建索引；否则讲解只能引用旧切片。

```powershell
cd zhixue\zhixue-ai
D:\Python3.12.10\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# 另开终端：
D:\Python3.12.10\python.exe tools\build_demo_index.py `
  --base-url http://127.0.0.1:8000 `
  --dsn 'mysql+pymysql://root:<口令>@127.0.0.1:3306/zhixue' `
  --bench
```

- 脚本只调用公开接口 `POST /api/rag/embed`，不直接写索引文件。
- 索引落盘在 `zhixue-ai/data/vector_index/`；该目录被 `.gitignore` 忽略，换机必须重建。
- 本机无 bge 模型时自动用 `hash-bigram`；装了 bge 会得到不同指标，不能混报。
- 如果启动时报“索引模式不一致”，停服务、删除 `data/vector_index/`、重启后再建。

2026-11-02 实测（hash-bigram，41 点 / 49 切片）：

| 指标 | 离线 `eval_retrieval.py`（第2—3章 20 点 / 28 切片） | 在线 41 点索引，threshold=0 | 在线 41 点索引，默认 0.35 |
| --- | --- | --- | --- |
| 查询数 | 60 | 60 | 60 |
| recall@5 | 88.3% | 85.0% | 76.7% |
| 知识点 top-1 | 68.3% | 60.0% | 58.3% |
| 空结果 | 7（覆盖 88.3%） | 0 | 4（覆盖 93.3%） |
| P50 / P95 | — | 5.1 / 6.7 ms | 5.9 / 7.8 ms |

入索引耗时：41 次 embed，P50 31.4 ms、P95 55.2 ms、合计约 1.41 s。
在线索引多了第1/4章切片，第2—3章 60 题的 recall@5 会从离线 88.3% 降到 85.0%，
这是“候选池变大”的正常代价，不是索引退化；报告时必须写清口径。

## 8. 覆盖率口径

父 POM 已接入 **JaCoCo 0.8.13**，只执行 `prepare-agent` + `report`，**不配置 check、不设阈值**。

- 报告位置：各模块 `target/site/jacoco/index.html`、`target/site/jacoco/jacoco.csv`。
- 因项目路径含中文与全角冒号，`destFile` 指向 `%TEMP%\zhixue-jacoco\<artifactId>.exec`，
  避免 `cmd.exe` 转码导致 agent 启动失败；报告仍写回模块 `target/`。
- 2026-11-02 `mvn -B -ntp verify`：**112 个测试，0 失败**；行覆盖 **65.0%（1809/2783）**、
  分支 **46.6%（595/1277）**、指令 **66.6%（9345/14035）**。仅统计有测试的 4 个模块
  （course/diagnosis/plan/bootstrap）；common/user/notification 无测试，未计入。
- 另有 `IntegrationFlowTest` 31 条 `@Tag("it")` 需要 `mvn -Pit verify` + Docker；
  本机无 Docker，**未运行**。
- 选“加 JaCoCo”而不是改验收口径的理由：先拿到真实基线，才能判断 06 号文里
  “覆盖率 ≥80%”指的是规则/错误码映射覆盖还是行覆盖；加报告不改任何门禁，
  也不会为了过阈值去写无效测试。`docs/06` 已补一句口径说明。
