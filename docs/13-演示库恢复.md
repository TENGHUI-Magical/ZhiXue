### 2.1 生成文件新鲜度自检

**任何一章的 `seed-*.sql` 改动后，必须先重跑生成脚本，再提交 `seed-demo-all.sql`：**

```powershell
pwsh -ExecutionPolicy Bypass -File .\scripts\build-seed-all.ps1
pwsh -ExecutionPolicy Bypass -File .\scripts\verify-seed-all-up-to-date.ps1
```

- 自检输出 `UP-TO-DATE ... SHA256=...`：生成文件与源 SQL 一致。
- 输出 `STALE ... 需要重跑 scripts/build-seed-all.ps1` 并列出“比生成文件新的源 SQL”：
  说明有人改了种子但没重生成，必须重跑后再提交。
- 以后接 CI 时建议在构建前跑 `pwsh scripts/verify-seed-all-up-to-date.ps1`；
  本次不改 `.github/workflows/ci.yml`。

注意：

- **已有 `data/mysql` 时 initdb 不会重跑**。要重新灌，先确认没有要保留的数据，
  备份后删除 `data/mysql`，再 `docker compose down && docker compose up -d`。
- 生产/真实试用环境不要执行合并种子里的演示账号段（固定演示口令）。
- 本机无 Docker 时，用 §3 的本机 MySQL 路径；两者种子内容等价。
- **本机没有 Docker，本节未真跑 `docker compose up`**：只做了合并文件静态检查 + 本机 MySQL
  从零执行等价验证；Docker entrypoint 的挂载/权限/字符集行为仍需在有 Docker 的机器补测。
