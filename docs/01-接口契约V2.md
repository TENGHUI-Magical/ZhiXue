## 0. 两份文件怎么配合

- **openapi.yaml**：唯一机器可读源。前端类型由它生成，Mock 由它生成，后端 springdoc 输出与它做双向校验。
- **本文**：解释"为什么这样定义、失败时怎么办、时序是什么"。若两者冲突，以 openapi.yaml 的字段为准、以本文的语义为准，并当场修 openapi.yaml。

禁止在本文中抄字段表。要改字段，改 openapi.yaml 并在此登记变更。

## 1. 通用约定

| 项 | 约定 |
| --- | --- |
| 前缀 | 所有业务接口 `/api`，健康检查 `/api/system/health` |
| 命名 | JSON 字段 camelCase；数据库 snake_case，由 MyBatis-Plus 映射 |
| 时间 | `Asia/Shanghai`；日期时间 `yyyy-MM-dd HH:mm:ss`；日期 `yyyy-MM-dd` |
| 空值 | 字段可空时显式返回 `null`，不省略字段 |
| 分页 | `page` 从 1 开始，`size` 默认 10、上限 50；响应 `{page,size,total,records}` |
| 排序 | 列表默认按 `createdAt` 倒序；章节按 `chapterNo` 升序 |
| 金额/评分 | 统一使用 0–1 小数，保留 3 位；教师评分用 1–5 整数 |
| 字符集 | 请求与响应 UTF-8；库、表、连接三处 utf8mb4 |
| 幂等 | 上传、创建错题、打卡必须带 `clientToken`；同用户同 token 重复请求返回首次结果，不重复写 |

### 1.1 鉴权

- 登录成功后返回 `token`，前端存 Pinia + localStorage，请求头 `satoken: <token>`。
- 角色只有 `STUDENT` / `TEACHER`；教师接口对学生返回 `40300`。
- `40100` 一律清 token 并跳登录页，不在当前页只弹提示（避坑 A3）。

### 1.2 请求追踪

- 每次请求由 Java 生成 `traceId`，透传到 FastAPI 与 `ai_generation_log.trace_id`。
- 响应头返回 `X-Trace-Id`，便于按 trace 查全链路日志。

## 2. 统一响应与错误码

响应固定 `{code, message, data, timestamp}`；`code=0` 为成功，HTTP 状态码仍按语义返回（400/401/403/404/409/500）。

| code | 含义 | 前端行为 |
| --- | --- | --- |
| 0 | 成功 | 解包 data |
| 40000 | 参数校验失败 | 表单字段级提示 |
| 40100 | 未登录或 token 过期 | 清 token，跳登录 |
| 40300 | 无权限 | 提示并返回上一页 |
| 40400 | 资源不存在 | 空态页 + 返回入口 |
| 40900 | 重复提交 / 状态冲突 | 提示"请勿重复提交"，刷新数据 |
| 42900 | 触发限流 | 显示剩余等待秒数，禁用提交按钮 |
| 50000 | 业务处理失败 | 通用错误卡片 + 重试 |
| 60000 | AI 服务不可用 | 展示历史讲解 + 稍后重试，允许手动录入 |
| 60001 | AI 超时（四级降级后仍失败） | 重试按钮 + 降级说明 |
| 60002 | OCR 失败 | 切手动录入表单，不阻断 |
| 60003 | 检索无匹配 | 提示手动选择知识点 / 按章节随机推荐 |
| 60004 | 合规拦截 | 展示学术诚信提示，不展示讲解正文 |

`40900 / 42900 / 60004` 为 V2 新增，需在 `ErrorCode` 中落地；未落地前不得在代码里使用魔法数字。

## 3. 状态机

| 对象 | 流转 | 触发 | 约束 |
| --- | --- | --- | --- |
| `ocr_task` | PENDING → RUNNING → SUCCESS / FAILED | 上传创建 → 后台执行 → 完成 | 超 60s 未完成标记 FAILED；允许重新上传 |
| `student_error_record` | DRAFT → CONFIRMED | 学生校正并确认知识点/错因 | 确认后不可回退；重复确认返回 40900 |
| `study_plan` / `study_plan_item` | PENDING → DONE / OVERDUE | 当日打卡 / 次日 0 点扫描 | OVERDUE 仅由定时任务写，不由前端传 |
| `ai_generation_log` | 生成 → 待评阅 → 已评阅 | 教师提交评分 | `reviewed_at` 为空即待评阅 |

### 3.1 主闭环时序

```
POST /api/error/upload        → 返回 taskId
GET  /api/error/tasks/{id}    → 轮询至 SUCCESS/FAILED（前端 2s 间隔，最多 30 次）
POST /api/error/records       → 创建 DRAFT（可先手填）
PUT  /api/error/records/{id}/confirm → CONFIRMED，写入 kpId/errorType
POST /api/diagnosis/explain   → SSE 生成讲解，落 ai_generation_log
GET  /api/recommendations     → 三层各 1 题
GET  /api/portraits/me        → 读取最新快照
```

确认接口内部按顺序执行：写库 → 触发推荐 → 标记画像待重算。**推荐失败不得回滚确认**，只在响应中返回空推荐并记录日志。

## 4. 上传与 OCR

- 端点 `POST /api/error/upload`，multipart 字段固定为 `file` + `clientToken`；字段名与 `openapi.yaml` 一致，前端不得自定义。
- 仅接受 `jpg/jpeg/png`，单文件 ≤5MB；服务端压缩到长边 ≤1600px 后再送 OCR。
- 手机照片先读 EXIF 方向并旋转（避坑 O2），再做灰度与二值化。
- 置信度 `<0.75` 时，响应中的字段仍返回，但前端必须高亮知识点选择框并禁止直接确认。
- 整页多题默认只取最大文本块；`PP-Structure` 版面分析作为 P1 增强，不在 MVP。
- 图片存 `data/upload/{userId}/{yyyyMM}/`，文件名用 UUID；删除错题不立即删图，由周任务清理 30 天前孤儿文件。

## 5. SSE 协议（讲解接口）

### 5.1 帧格式

标准 SSE，服务端逐帧发送 `event: <type>` + `data: <json>`，帧间以空行分隔。前端按 `\n\n` 切帧并保留残余缓冲区（避坑 S6），**禁止使用 EventSource**（只支持 GET、不能带 header，避坑 S1）。

| 事件 | 时机 | data 结构 |
| --- | --- | --- |
| `meta` | 建连后立即 | `{explainId, traceId, model, degraded}` |
| `source` | 首段正文前 | `{kpId, textbookPage, title}`，可多次 |
| `delta` | 生成过程中 | `{text}`，增量文本 |
| `degraded` | 发生降级时 | `{level: "L2"/"L3", reason}` |
| `done` | 正常结束 | `{explainId, latencyMs, tokens, cached?}`；命中缓存时 `cached=true` |
| `error` | 失败 | `{code, message, retryable}` |

### 5.2 超时与心跳

| 超时 | 值 | 行为 |
| --- | --- | --- |
| 连接超时 | 3s | 前端判定后端不可达，展示错误卡片 |
| 首字节超时 | 10s | 未收到 `meta` 即中止，触发降级提示 |
| 整体超时 | 60s | 服务端结束流并发 `error` |

服务端每 15 秒发送 `: heartbeat` 注释行（无 event/data），前端忽略。流式只卡首字节，不得用 10 秒卡整体（避坑 S5）。

### 5.3 取消与清理

- `SseEmitter.onCompletion` / `onTimeout` 必须取消上游 WebClient 订阅，避免用户关页后模型空跑（避坑 S3）。
- 客户端断开后仍要落库已生成内容，`ai_generation_log.is_degraded` 与 `latency_ms` 照常记录。
- Nginx 需 `proxy_buffering off`、`proxy_read_timeout 300s`（避坑 S4）。

### 5.4 断线恢复

- `explainId` 在 `meta` 中下发；刷新页面后可用 `GET /api/diagnosis/explain/{explainId}` 取已生成全文。
- 不做自动重连续传；重连等同新建一次请求，命中缓存则直接回放。

## 6. 降级链与错误映射

| 级别 | 触发 | 处理 | 标记 |
| --- | --- | --- | --- |
| L1 | 默认 | DeepSeek-V3，temperature 0.3 | `degraded=false` |
| L2 | L1 超时/5xx/限流，重试 1 次仍失败 | GLM-4-Flash，同参数 | `degraded=true, level=L2` |
| L3 | L1/L2 均失败或断网 | 本地模板：`concept_text` + `misconception` + 固定结构 | `degraded=true, level=L3` |
| L4 | L3 所需知识点原文缺失 | 返回 `60001` | `level=L4` |

- 降级不得返回空白正文；L3 必须带来源 `[KP0201·教材P34]`，保证溯源率 100%。
- Redis 不可用时跳过缓存直调模型，不得因缓存故障返回 500。
- 同一讲解请求的缓存 key 为 `sha1(kpId + errorType + correctedText)`，TTL 7 天；`forceRefresh=true` 跳过缓存。
- 缓存只保存 L1 正常完成、未降级且未拦截的正文；L2/L3 结果不写缓存，避免把降级结果固化 7 天。缓存命中按 `meta → source → delta(全文) → done` 回放，留痕 `model=cache`。

## 7. 端点语义（不列字段）

| 组 | 端点 | 语义与约束 |
| --- | --- | --- |
| auth | `POST /login`、`POST /logout`、`GET /me` | 登录返回 token 与角色；登出使 token 失效 |
| course | `GET /courses`、`/chapters`、`/knowledge-graph`、`/course/kp/{id}` | 只返回 `is_active=1`；图谱默认返回全部先修边 |
| error | `POST /upload`、`GET /tasks/{id}`、`POST /records`、`GET /records`、`GET /records/{id}`、`PUT /confirm` | 上传只建任务，不建错题；创建错题允许字段不全（DRAFT） |
| diagnosis | `POST /map`、`POST /explain`(SSE)、`GET /explain/{id}` | 映射返回 `decision`；讲解必须先有 CONFIRMED 记录 |
| recommend | `GET /recommendations?logId=` | 返回 1–3 条，按 CONSOLIDATE/VARIANT/ADVANCE 排序 |
| practice | `POST /practices` | 提交推荐题/自主练习作答，写 `practice_record`（RECOMMEND/SELF）；带 `recommendationId` 时置 `is_adopted=1`；计划内作答走 `/plans/{planId}/checkin`（source=PLAN） |
| portrait | `GET /portraits/me`、`GET /portraits/class/{courseId}` | 只读快照表，不在请求内实时聚合 |
| plan | `GET /plans`、`POST /plans/generate`、`POST /plans/{planId}/checkin` | 一次生成 7 条日计划，周视图由前端聚合；打卡写 `practice_record(source=PLAN)` 并更新 `done_count`，同一 qId 只记一次 |
| teacher | `GET /reviews`、`POST /reviews/{logPk}`、知识点/题库 CRUD、Excel 导入 | 评阅写回 `ai_generation_log`；导入单次 ≤500 行 |
| system | `GET /health` | 返回 db/redis/ai 三态，任一 DEGRADED 不返回 5xx |

### 7.1 知识点维度归属

- `course.dimension_json` 为数组：`[{key, name}]`，只定义维度的 key、展示名与雷达图顺序。
- 维度归属的唯一事实源是 `knowledge_point.dimension_key`（V2.1 新增列）；`dimension_json` 不存 `kpIds`，避免两处维护漂移。
- 创建知识点时必须传 `dimensionKey`，服务端校验该 key 存在于课程配置，否则 `40000`。
- 画像快照用 `dimension_scores` JSON 存储，键与 `dimension_json.key` 一致（DDL 见 `init-v2.sql` 的 V2.1 基线；旧库执行 `init-v2.1-migration.sql`）。

## 8. 幂等与并发

| 场景 | 方案 |
| --- | --- |
| 上传 | `(user_id, client_token)` 唯一；重复请求返回原 taskId |
| 创建错题 | `(user_id, client_token)` 唯一；重复返回原 logId |
| 确认错题 | 行级状态判断 + 更新条件 `status='DRAFT'`；影响行数 0 返回 40900 |
| 打卡 | 计划明细按 `uk_plan_q(plan_id, q_id)` 防同题重复 + `is_done` 判重；打卡写 `practice_record(source=PLAN)`，幂等由其 `(user_id, client_token)` 唯一键负责 |
| 作答提交 | `practice_record` 上 `(user_id, client_token)` 唯一；重复请求返回首次结果并带 `duplicate=true` |
| 评阅 | `reviewed_at` 为空才允许写，重复评阅返回 40900 |
| 限流 | 讲解接口按用户 10 次/分钟；超出 42900，带 `Retry-After` |
